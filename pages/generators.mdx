# 🧱 Code & Asset Generators

Rabin CLI generators automate repetitive boilerplate while keeping code strictly organized according to Clean Architecture and your design system.

---

## 🚀 Generator Overview

| Command | Short Alias | Output Description |
|---|---|---|
| `rabincli assets` | `assets` | Scans `assets/` and generates type-safe `Assets` constants class |
| `rabincli feature <name>` | `feature`, `f` | Complete Clean Architecture feature (domain, data, application, presentation, screens, controller & route) |
| `rabincli add model <name>` | `add m` | Synced Entity, DTO, Mapper, Drift Table/DAO, Repo impl, Migration & RLS |
| `rabincli add screen <name>` | `add s` | Screen widget + Riverpod controller + automatic route injection |
| `rabincli add component <name>` | `add c` | Token-driven reusable component with `@Preview` and widget test |
| `rabincli add provider <name>` | `add p` | Typed `@riverpod` provider with codegen annotations |
| `rabincli add migration <name>` | | Timestamped Supabase SQL migration + Drift schema version bump |
| `rabincli add lang <code>` | | New ARB localization file & delegate registration |

## 🔄 Synced Model Generator (`add m`)

When you create a model with Rabin CLI:

```bash
rabincli add m habit --feature habits --fields "title:string,reminder_time:string,is_completed:bool"
```

Rabin CLI automatically generates:
1. **Domain Entity** (`lib/features/habits/domain/entities/habit.dart`): Pure immutable Dart class with `Equatable`.
2. **Data DTO & Mapper** (`lib/features/habits/data/models/habit_dto.dart`): `fromJson`, `toJson`, and `toEntity()`.
3. **Drift SQLite Table & DAO** (`lib/features/habits/data/datasources/habits_table.dart`): Reactive local queries with `sync_status` tracking.
4. **Supabase SQL Migration** (`supabase/migrations/<timestamp>_create_habits_table.sql`): Table definition with `updated_at` trigger and Row Level Security (RLS) tenant isolation.
5. **Drift Marker Registration**: Automatically registers the new table into `core/database/app_database.dart` above `// supafire:tables`.

## 🎨 Strongly-Typed Asset Generator (`rabincli assets`)

Never use raw fragile strings like `Image.asset('assets/images/logo.png')` or `SvgPicture.asset('assets/icons/bell.svg')`. 

Following the best practices in [You are using assets in flutter app the wrong way](https://blog.rabinacharya.info.np/you-are-using-assets-in-flutter-app-the-wrong-way), Rabin CLI organizes your assets into semantic folders (`assets/images`, `assets/icons`, `assets/vectors`, `assets/fonts`), automatically declares them in `pubspec.yaml`, and generates strongly-typed accessor classes:

```bash
# Scan assets and compile typed constants
rabincli assets

# Or if you also use fluttergen:
rabincli assets --flutter-gen
```

### Generated Code (`lib/core/constants/app_assets.dart`)

```dart
abstract final class Assets {
  static const icons = _IconsAssets();
  static const images = _ImagesAssets();
  static const vectors = _VectorsAssets();
}

class _IconsAssets {
  const _IconsAssets();
  final notificationIcon = const SvgAsset('assets/icons/notification_icon.svg');
}

class _ImagesAssets {
  const _ImagesAssets();
  final userAvatar = const ImageAsset('assets/images/user_avatar.png');
}
```

### Type-Safe Usage in Widgets

```dart
// Render an SVG with autocomplete, size, and color tinting
Assets.icons.notificationIcon.svg(
  width: 24, 
  height: 24, 
  color: context.colors.primary,
)

// Render an Image with fit and dimensions
Assets.images.userAvatar.image(
  width: 48, 
  height: 48, 
  fit: BoxFit.cover,
)

// Access raw path whenever required
final path = Assets.icons.notificationIcon.path;
```
